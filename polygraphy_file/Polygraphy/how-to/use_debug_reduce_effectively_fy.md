简介
debug reduce 子工具允许您迭代地缩减失败的 ONNX 模型，
以找到一个最小失败案例，这通常比原始模型更容易调试。
debug reduce 执行的基本步骤如下：
从原始图中移除部分节点，并将新模型写入 polygraphy_debug.onnx
（可使用 --iter-artifact 选项更改此路径）。
以交互方式评估模型，或者如果提供了 --check 命令，则自动进行评估。
如果模型仍然失败，则继续移除更多节点；否则加回节点；然后重复该过程。
本指南提供了一些通用信息以及高效使用 debug reduce 的技巧和建议。
另请参阅 `debug` 子工具的通用操作指南，
其中包含适用于所有 debug 子工具的信息。
关于动态输入形状模型的说明
对于具有动态输入形状的模型，您可能并不总是知道模型中所有中间张量的形状。因此，在检查子图时，可能会误用不正确的张量形状。
有两种方法可以解决这个问题：
使用 polygraphy surgeon sanitize --override-input-shapes <shapes> 冻结模型中的输入形状。
向 debug reduce 提供 --model-input-shapes，这将利用形状推断来推导中间张量的形状。
如果您的模型使用了形状操作（shape operations），通常最好使用选项 (1)，并通过 --fold-constants 将形状操作折叠消除。
无论哪种情况，如果形状推断出现问题，都可以使用
--force-fallback-shape-inference 通过实际运行推理来推断形状。
或者，您可以使用 --no-reduce-inputs 以确保模型输入不被修改。
每次迭代生成的 polygraphy_debug.onnx 子图将始终使用原始模型的输入；只有末尾的层会被移除。
调试精度错误
精度错误的调试尤为复杂，因为图中早期层引入的错误可能会被后续层放大，从而难以确定哪一层才是真正的错误根源。本节概述了在使用 debug reduce 调试精度错误时需要牢记的一些事项。
容差
在某些模型架构中，中间层可能存在较大误差，但这不一定导致最终模型输出出现精度问题。因此，请确保用于比较的容差足够高，以忽略此类假阳性结果。
同时，容差必须足够低，以便捕获真正的错误。
一个好的起点是将容差设置为接近您在完整模型中观察到的误差水平。
生成基准值（Golden Values）
在生成用于比较的基准值时，可以采取两种不同的方法，它们各有优缺点：
提前为所有层生成基准值。
提前生成基准值时，您需要确保每个子图的输入值来自基准值。否则，将子图的输出与基准值进行比较将毫无意义。
有关此方法的详细信息，请参阅示例。
为每个子图单独生成基准值。
为每个子图重新生成基准值可能需要较少的手动操作，但缺点是它不一定能准确复现子图在更大图上下文中的行为。
例如，如果模型中的错误是由原始模型某个中间层的溢出引起的，那么为每个子图生成全新的输入值可能无法复现该错误。
技巧与建议
保存中间模型
在某些情况下，能够访问缩减过程中生成的每一个模型是非常有用的。这样，即使缩减提前退出或未能生成最小模型，您仍有可用的素材。此外，您可以手动比较各种通过和失败的子图以识别规律，这可能有助于您确定错误的根本原因。
您可以向 debug reduce 指定 --artifacts polygraphy_debug.onnx，以自动将每次迭代的模型分类到 good 和 bad 目录中。文件名包含迭代编号，以便您轻松将其与缩减期间的日志输出相关联。
从最小通过模型中获取洞察
除了最小失败模型外，debug reduce 还可以生成最小通过模型。通常，这是指大小最接近最小失败模型的通过模型。将此模型与最小失败模型进行对比，可以获得关于故障根本原因的额外洞察。
要使 debug reduce 保存最小通过模型，请使用 --min-good <path> 选项。
缩减模式
debug reduce 提供了多种缩减模型的策略，您可以通过 --mode 选项指定：
bisect（二分法）的时间复杂度为 O(log(N))，而 linear（线性法）的时间复杂度为 O(N)，但可能会产生更小的模型。
一个折中的好方法是先对原始模型使用 bisect，然后使用 linear 进一步缩减结果。
