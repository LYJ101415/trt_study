简介
debug 子工具遵循相同的一般原则：
迭代执行某项任务以生成特定输出
评估生成的输出，判定其应被视为 good（通过）还是 bad（失败）
根据 (2) 的判定结果，将跟踪的产物分类到 good 和 bad 目录中
根据需要做出更改，然后重复上述过程
本指南提供了一些通用信息以及高效使用 debug 子工具的技巧和建议。

技巧与建议
使用交互模式入门
在 debug 子工具中，自动模式（即提供了 --check 命令时）提供了一种完全无需人工干预的方法。然而，如果您刚刚上手，这种方式可能更难使用和理清逻辑。
Polygraphy 中的 debug 工具还提供了交互模式，该模式会提示并引导您完成整个流程。
要使用交互模式，只需省略 --check 选项即可。
例如，使用 debug reduce 时：
polygraphy debug reduce <model.onnx> -o <reduced.onnx>

什么算作“失败”？
在自动模式下（即提供了 --check 命令时），debug 子工具默认认为非零退出状态码表示失败。但在某些情况下，这种假设可能并不理想：
您可能希望忽略某些类型的失败，以便获得一个仅以非常特定的方式失败的最小模型。
您的 --check 命令可能根本不会以非零状态码退出！
相反，您可能希望根据该命令的输出内容而非其退出状态码来触发失败判定。
针对这些情况，您可以使用 --fail-regex 选项。仅当 --check 命令输出（stdout 或 stderr）的某部分内容匹配指定的正则表达式时，才会触发失败判定。
