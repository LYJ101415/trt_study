# Comparing With Custom Input Data

## Introduction

In some cases, we may want to run comparisons using custom input data.
Polygraphy provides multiple ways to do so, which are detailed [here](../../../../how-to/use_custom_input_data.md).

In this example, we'll demonstrate 2 different approaches:

1. Using a data loader script by defining a `load_data()` function in a Python script (`data_loader.py`).
    Polygraphy will use `load_data()` to generate inputs at runtime.

2. Using a JSON file containing pre-generated inputs.
    For convenience, we'll use our script from above (`data_loader.py`) to save the inputs
    generated by `load_data()` to a file called `custom_inputs.json`.

*TIP: Generally, a data loader script is preferrable when working with large amounts of input data*
    *as it avoids the need to write to the disk.*
    *On the other hand, JSON files may be more portable and can help ensure reproducibility.*

Finally, we'll supply our custom input data to `polygraphy run` and compare outputs between
ONNX-Runtime and TensorRT.

Since our model has dynamic shapes, we'll need to set up a TensorRT Optimization Profile.
For details on how we can do this via the command-line,
see [`convert` example 03](../../convert/03_dynamic_shapes_in_tensorrt).
For simplicitly, we'll create a profile where `min` == `opt` == `max`.

*NOTE: It is important that our optimization profile works with the shapes provided by our*
    *custom data loader. In our very simple case, the data loader always generates inputs of*
    *shape (1, 2, 28, 28), so we just need to ensure this falls within [`min`, `max`].*

## Running The Example

1. Run the script to save input data to the disk.
    *NOTE: This is only necessary for option 2.*
    ```bash
    python3 data_loader.py
    ```

2. Run the model with TensorRT and ONNX-Runtime using custom input data:
    - Option 1: Using the data loader script:

    ```bash
    polygraphy run dynamic_identity.onnx --trt --onnxrt \
        --trt-min-shapes X:[1,2,28,28] --trt-opt-shapes X:[1,2,28,28] --trt-max-shapes X:[1,2,28,28] \
        --data-loader-script data_loader.py
    ```

    - Option 2: Using the JSON file containing the saved inputs:

    ```bash
    polygraphy run dynamic_identity.onnx --trt --onnxrt \
        --trt-min-shapes X:[1,2,28,28] --trt-opt-shapes X:[1,2,28,28] --trt-max-shapes X:[1,2,28,28] \
        --load-inputs custom_inputs.json
    ```

下面我将从设计目标、两种方法详解、动态形状处理、实际代码示例、适用场景对比和工程最佳实践六个维度，为你深度解析。

 一、核心目标与解决的问题
 为什么需要“自定义输入数据”？默认情况下，polygraphy run 使用随机生成的输入（基于模型输入 shape）;但在以下场景中，这不够用：需要用真实图像/传感器数据验证模型;需要特定边界值（如全零、极大值）测试鲁棒性;需要固定输入以确保多次运行结果可复现（用于回归测试）;模型有动态输入形状，需提供符合 profile 的具体实例
 Polygraphy 的解决方案：支持通过 Python 数据加载脚本 或 预存 JSON 文件 提供任意输入数据。

 二、方法一：使用数据加载脚本（--data-loader-script）
工作原理:编写一个 Python 脚本（如 data_loader.py）;定义一个名为 load_data() 的函数（无参）;该函数返回一个 字典：{"input_name": numpy_array, ...};Polygraphy 在每次推理前调用此函数获取输入;示例 data_loader.py 内容:
import numpy as np

def load_data():
    """
    返回一个包含单个 batch 的输入数据。
    注意：shape 必须与 TRT optimization profile 兼容！
    """
    # 生成 shape (1, 2, 28, 28) 的 float32 随机数据
    return {"X": np.random.randn(1, 2, 28, 28).astype(np.float32)}

CLI 调用:
polygraphy run dynamic_identity.onnx --trt --onnxrt \
    --trt-min-shapes X:[1,2,28,28] \
    --trt-opt-shapes X:[1,2,28,28] \
    --trt-max-shapes X:[1,2,28,28] \
    --data-loader-script data_loader.py
 优势
内存高效：数据按需生成，不写磁盘（适合大数据集）
动态灵活：可在 load_data() 中实现复杂逻辑（如读取文件、数据增强）
支持多组输入：可通过多次调用生成不同样本（用于批量测试）
 三、方法二：使用预存 JSON 文件（--load-inputs）
工作原理:先用脚本（或其它方式）生成并保存输入数据到 JSON;
JSON 格式：Polygraphy 自定义的序列化格式（含 dtype、shape、base64 编码数据）
CLI 直接加载该文件作为输入;生成 JSON 的方式（利用上述 data_loader.py）
# 在 data_loader.py 末尾添加：
if __name__ == "__main__":
    from polygraphy.json import save_json
    inputs = load_data()
    save_json(inputs, "custom_inputs.json")
    print("Saved inputs to custom_inputs.json")
然后运行：
python3 data_loader.py  # 生成 custom_inputs.json
CLI 调用:
polygraphy run dynamic_identity.onnx --trt --onnxrt \
    --trt-min-shapes X:[1,2,28,28] \
    --trt-opt-shapes X:[1,2,28,28] \
    --trt-max-shapes X:[1,2,28,28] \
    --load-inputs custom_inputs.json
 优势:
完全可复现：固定输入，确保每次运行结果一致
便于分享：JSON 文件可直接发给同事复现问题
调试友好：可人工检查输入内容（虽然 base64 需解码）
 四、动态形状（Dynamic Shapes）的关键处理
问题背景:模型输入 shape 不固定（如 X: [-1, 2, -1, -1]）;TensorRT 要求构建时指定 Optimization Profile（min/opt/max）;文档中的简化策略
--trt-min-shapes X:[1,2,28,28] \
--trt-opt-shapes X:[1,2,28,28] \
--trt-max-shapes X:[1,2,28,28]
即：min = opt = max → 实际上将动态 shape “固化”为静态 shape

 重要约束:自定义输入的 shape 必须落在 [min_shape, max_shape] 范围内！
例如：
若 profile 是 min=[1,2,16,16], max=[1,2,64,64];则 load_data() 可返回 (1,2,32,32)，但不能返回 (1,2,8,8);更真实的动态 shape 示例
# data_loader.py —— 随机选择合法 shape
def load_data():
    h = w = np.random.choice([16, 32, 48, 64])
    return {"X": np.random.randn(1, 2, h, w).astype(np.float32)}

# CLI 设置宽泛 profile
polygraphy run ... \
    --trt-min-shapes X:[1,2,16,16] \
    --trt-opt-shapes X:[1,2,32,32] \
    --trt-max-shapes X:[1,2,64,64] \
    --data-loader-script data_loader.py
 五、两种方法对比与选型建议
特性	数据加载脚本 (--data-loader-script)	   JSON 文件 (--load-inputs)
内存占用	低（按需生成）	                    高（全量加载到内存）
磁盘 I/O	无	                              需读取文件
可复现性	依赖随机种子	                   完全确定
灵活性	   高（可编程）	                      低（固定数据）
适用场景	大数据集、随机测试、CI 流水线	   调试、问题复现、小规模验证
共享难度	需共享脚本+依赖	                  只需共享 JSON 文件

 经验法则：
开发调试阶段 → 用 JSON（确保可复现）
大规模回归测试 → 用数据加载脚本（避免磁盘瓶颈）

 六、完整工作流示例
场景：验证 TRT 引擎在真实图像上的精度
Step 1: 编写数据加载器（读取图像）
# image_loader.py
import cv2
import numpy as np

def load_data():
    img = cv2.imread("test.jpg")  # HWC, BGR
    img = cv2.resize(img, (224, 224))
    img = img.transpose(2, 0, 1)[None, ...]  # NHWC -> NCHW
    img = img.astype(np.float32) / 255.0
    return {"input": img}
Step 2: 运行对比（假设模型输入名是 "input"）
polygraphy run model.onnx --trt --onnxrt \
    --trt-min-shapes input:[1,3,224,224] \
    --trt-opt-shapes input:[1,3,224,224] \
    --trt-max-shapes input:[1,3,224,224] \
    --data-loader-script image_loader.py \
    --atol 1e-3 --rtol 1e-3
Step 3: 若失败，保存输入用于复现
# 在 image_loader.py 中临时添加：
if __name__ == "__main__":
    from polygraphy.json import save_json
    save_json(load_data(), "debug_input.json")
之后可用 --load-inputs debug_input.json 精确复现问题。
