# Inspecting Inference Outputs


## Introduction

The `inspect data` subtool can display information about the
`RunResults` object generated by `Comparator.run()`, which represents inference outputs.


## Running The Example

1. Generate some inference outputs using ONNX-Runtime:

    ```bash
    polygraphy run identity.onnx --onnxrt --save-outputs outputs.json
    ```

2. Inspect the results:

    ```bash
    polygraphy inspect data outputs.json --show-values
    ```

    This will display something like:

    ```
    [I] ==== Run Results (1 runners) ====

        ---- onnxrt-runner-N0-07/15/21-10:46:07 (1 iterations) ----

        y [dtype=float32, shape=(1, 1, 2, 2)] | Stats: mean=0.35995, std-dev=0.25784, var=0.066482, median=0.35968, min=0.00011437 at (0, 0, 1, 0), max=0.72032 at (0, 0, 0, 1), avg-magnitude=0.35995, p90=0.62933, p95=0.62933, p99=0.71123
            [[[[4.17021990e-01 7.20324516e-01]
               [1.14374816e-04 3.02332580e-01]]]]
    ```
==============================================================================
这份文档展示了 如何使用 Polygraphy 的 inspect data 工具来深入分析推理输出结果（inference outputs）。这是模型精度验证、数值稳定性检查和调试推理差异的关键环节。

下面从核心概念、流程解析、输出详解、统计指标含义、高级用法、工程价值六个维度进行深度解析。
一、核心概念：什么是 RunResults？在 Polygraphy 中：Comparator.run() 是执行多后端（如 ONNX Runtime、TensorRT）推理并收集输出的核心函数,RunResults 是其返回的对象，结构如下：
{
  "runner_name": [  # 如 "onnxrt-runner-N0-..."
      { "output_name": np.ndarray },  # 第1次迭代输出
      { "output_name": np.ndarray },  # 第2次迭代输出（若多次运行）
      ...
  ]
}
outputs.json 是 RunResults 的 JSON 序列化形式（支持 NumPy 数组）
 inspect data 就是专门用于可视化和分析这种结构化推理结果的工具。

二、完整流程解析
步骤 1：生成推理输出
polygraphy run identity.onnx --onnxrt --save-outputs outputs.json
使用 ONNX Runtime 运行 identity.onnx,将输出保存为 outputs.json,
默认使用 随机输入（可通过 --load-inputs 指定固定输入）
步骤 2：检查输出内容
polygraphy inspect data outputs.json --show-values
--show-values：关键参数，显示张量的具体数值（否则只显示统计信息）
三、输出结构深度解读
示例输出：
[I] ==== Run Results (1 runners) ====

    ---- onnxrt-runner-N0-07/15/21-10:46:07 (1 iterations) ----

    y [dtype=float32, shape=(1, 1, 2, 2)] | Stats: mean=0.35995, std-dev=0.25784, ... 
        [[[[4.17021990e-01 7.20324516e-01]
           [1.14374816e-04 3.02332580e-01]]]]
逐层解析：
1. 全局信息
==== Run Results (1 runners) ====
表示包含 1 个推理后端（runner） 的结果
2. Runner 元数据
---- onnxrt-runner-N0-07/15/21-10:46:07 (1 iterations) ----
onnxrt-runner：后端类型（ONNX Runtime）
N0：Runner 编号（支持多 runner 对比）
07/15/21-10:46:07：时间戳（用于区分多次运行）
(1 iterations)：执行了 1 次推理（默认 1 次，可用 --iterations 增加）
3. 张量详情
y [dtype=float32, shape=(1, 1, 2, 2)]
y：输出张量名称（来自 ONNX 模型）
dtype=float32：数据类型
shape=(1,1,2,2)：张量形状
4. 统计摘要（Stats）
mean=0.35995, std-dev=0.25784, var=0.066482, median=0.35968, 
min=0.00011437 at (0, 0, 1, 0), max=0.72032 at (0, 0, 0, 1), 
avg-magnitude=0.35995, p90=0.62933, p95=0.62933, p99=0.71123
 统计指标详解：
指标	        含义	     调试价值
mean	       均值	        判断整体偏移
std-dev	       标准差	    衡量数值离散程度
var	           方差	        同上，单位不同
median	       中位数	    对异常值不敏感
min/max	   最小/最大值 + 位置索引	定位 NaN/Inf/超大值
avg-magnitude	平均绝对值	       判断信号强度
p90/p95/p99	90%/95%/99% 分位数	   分析尾部极端值

 关键亮点：min=... at (0,0,1,0) 直接给出异常值位置，极大加速调试！

5. 具体数值（--show-values）
[[[[4.17021990e-01 7.20324516e-01]
   [1.14374816e-04 3.02332580e-01]]]]
以 NumPy 风格 显示张量内容;科学计数法（e-01 = ×10⁻¹）便于阅读小数

四、高级用法与技巧
1. 多 Runner 对比（核心场景）
# 保存两个后端的输出
polygraphy run model.onnx --onnxrt --save-outputs ort.json
polygraphy run model.onnx --trt --save-outputs trt.json

# 合并检查（需先用 `data load` 合并）
polygraphy data load ort.json trt.json -o combined.json
polygraphy inspect data combined.json --show-values
输出会显示 多个 runner 的对比;可快速发现 TRT vs ORT 的数值差异
2. 仅查看统计信息（大张量时推荐）
polygraphy inspect data outputs.json  # 不加 --show-values
避免刷屏（如 1000x1000 的 heatmap）
3. 结合精度检查
# 先运行比较
polygraphy run model.onnx --onnxrt --trt --validate

# 再 inspect 差异大的输出
polygraphy inspect data outputs.json --show-values
4. 自定义输入下的输出分析
polygraphy run model.onnx --onnxrt --load-inputs fixed_inputs.json --save-outputs outputs.json
polygraphy inspect data outputs.json --show-values
确保每次 inspect 的是相同输入下的输出

五、工程价值：为什么需要 inspect inference outputs？
场景 1：定位精度问题;发现 max=1e20 → 存在数值溢出;std-dev=0 → 所有输出相同（死神经元？）;TRT 输出全零，ORT 正常 → FP16 下溢
场景 2：验证模型正确性;Identity 模型：输出应 ≈ 输入;分类模型：检查 softmax 输出是否合理（0~1，和为1）
场景 3：调试自定义插件;比较插件输出 vs CPU 参考实现;通过 min/max 位置快速定位计算错误
场景 4：性能-精度权衡;启用 TensorRT 的 fp16 后：
polygraphy inspect data fp32.json fp16.json
观察 std-dev 和 p99 差异，评估精度损失
六、注意事项与局限性
注意点	                      说明
大张量慎用 --show-values	可能输出数 MB 文本
JSON 文件体积大	NumPy 数组以 base64 存储，可用 --save-outputs --save-inputs 时加 --no-save-base64（但会丢失 dtype/shape）
仅支持 Polygraphy 格式	    不能直接 inspect TensorFlow/TensorRT 原生输出文件

多 batch 需注意	统计信息是对整个 batch 计算的
 总结：inspect data 的核心价值
维度	    说明
本质	    推理输出的“显微镜+统计仪表盘”
核心能力	同时提供 具体数值 + 全面统计 + 异常定位
不可替代性	比 print(tensor) 更结构化，比 TensorBoard 更轻量
典型用户	模型部署工程师、精度调试人员、插件开发者

 终极建议：当你面对“为什么结果不对？”的问题时，不要猜测，用 polygraphy inspect data --show-values 看一眼。那个 min=... at (...) 的提示，往往就是问题的突破口。
因此，尽管命令简单，但它是连接 模型理论输出 与 实际推理行为 的关键桥梁，是 AI 推理调试工作流中不可或缺的一环。
