# Interoperating With TensorRT


## Introduction

A key feature of Polygraphy is complete interoperability with TensorRT, as well as
with other backends. Since Polygraphy does not hide the underlying backend APIs,
it is possible to freely switch between using the Polygraphy API and a backend API,
such as TensorRT.

In this example, we'll look at how you can retain access to the advanced functionality
provided by a backend without giving up the conveniences provided by Polygraphy - the
best of both worlds.

Polygraphy provides an `extend` decorator which can be used to easily extend existing
Polygraphy loaders. This can be useful in many scenarios, but for this example,
we will focus on cases where you may want to:
- Modify the TensorRT network prior to building the engine
- Use a TensorRT builder flag not currently supported by Polygraphy


## Running The Example

1. Install prerequisites
    * Ensure that TensorRT is installed
    * Install other dependencies with `python3 -m pip install -r requirements.txt`


2. **[Optional]** Inspect the TensorRT network generated by `load_network()`.
    This will invoke `load_network()` from within the script and display the
    generated TensorRT network, which should be named `"MyIdentity"`:

    ```bash
    polygraphy inspect model example.py --trt-network-func load_network --show layers attrs weights
    ```

3. Run the example:

    ```bash
    python3 example.py
    ```

下面将从背景、设计思想、关键技术点、运行说明四个方面进行详细解析。

一、背景与核心理念
原文：

A key feature of Polygraphy is complete interoperability with TensorRT, as well as with other backends. Since Polygraphy does not hide the underlying backend APIs, it is possible to freely switch between using the Polygraphy API and a backend API, such as TensorRT.

解析：
Polygraphy 的设计哲学：不封装、不隐藏底层推理框架（如 TensorRT、ONNX Runtime）的 API。
用户既可享受 Polygraphy 提供的高层抽象（如一行代码构建引擎、统一 Runner 接口），又可在需要时直接操作原生 TensorRT 对象（如 INetworkDefinition, IBuilderConfig）。
这种“透明互操作”能力，使得 Polygraphy 既适合快速原型开发，也适用于需要精细控制的生产场景。
关键优势：避免“被框架绑架”——你永远可以下钻到更底层。

二、典型应用场景
文档明确指出两个常见需求：

在构建引擎前修改 TensorRT 网络结构
例如：插入调试层、替换算子、添加输出节点以便中间特征可视化。
使用 Polygraphy 尚未封装的 TensorRT 构建标志（Builder Flags）
例如：启用新的精度模式（如 FP8）、设置特定硬件优化选项。
这些需求在模型部署调优中非常常见，而 Polygraphy 通过灵活的扩展机制支持它们。

三、关键技术：@extend 装饰器
原文：

Polygraphy provides an extend decorator which can be used to easily extend existing Polygraphy loaders.

深入解析：
什么是 “Loader”？

在 Polygraphy 中，Loader 是一个可调用对象（callable），用于延迟加载资源（如 ONNX 模型、TensorRT 引擎）。例如：
Python
编辑
from polygraphy.backend.onnx import NetworkFromOnnxPath
loader = NetworkFromOnnxPath("model.onnx")  # 此时尚未加载
network, parser = loader()                  # 调用时才真正加载
@extend 的作用：

允许你在不修改原始 Loader 实现的前提下，拦截并增强其返回值。特别适用于对 TensorRT 网络或构建配置进行后处理。
典型工作流程（以修改网络为例）：
使用 Polygraphy 的 NetworkFromOnnxPath 加载 ONNX 并转换为 TensorRT 网络；
用 @extend 装饰一个函数，接收 (network, parser)；
在该函数中直接调用原生 TensorRT API 修改 network（如 network.add_output(...)）；
返回修改后的 (network, parser)；
后续 Polygraphy 组件（如 EngineFromNetwork）会使用这个增强后的网络。
好处：保持代码模块化，无需复制粘贴整个加载逻辑。

四、运行说明详解
步骤 1：安装依赖
标准流程，确保 TensorRT 和 Polygraphy 及其依赖已安装。

步骤 2（可选）：使用 polygraphy inspect 查看网络
polygraphy inspect model example.py --trt-network-func load_network --show layers attrs weights
命令解析：
polygraphy inspect model：Polygraphy 内置的模型检查工具。
example.py：指定包含目标函数的 Python 文件。
--trt-network-func load_network：告诉工具去调用 example.py 中的 load_network() 函数来获取 TensorRT 网络。
--show layers attrs weights：显示网络的层结构、属性和权重。
用途：
调试网络修改是否生效（例如确认是否成功添加了新输出）；验证模型结构正确性；
无需编写额外打印代码，Polygraphy 提供开箱即用的可视化。
这体现了 Polygraphy 的另一个优势：强大的内省（introspection）能力。

步骤 3：运行主程序
python3 example.py
执行实际的推理或验证逻辑（具体行为取决于 example.py 的实现，通常会构建引擎并运行理）。
